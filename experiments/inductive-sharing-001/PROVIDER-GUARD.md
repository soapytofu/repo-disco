# Provider proof-body guard v1

Separate offline guard for the validated revision-003 inductive family; old client parsers and experimental results remain unchanged. No model requests or new verifier runs were made for this guard.

The response must contain one unambiguous JSON object with exactly `Facts.dfy` as a string value, optionally surrounded by prose or fences. Standard JSON decoding and outer-file whitespace normalization are the only transformations. The guard identifies the original, exact protected helper headers, finds proof bodies using balanced braces, and compares the full masked provider skeleton byte-for-byte. Total's definition, exports, signatures, parameters, contracts, induction attributes, decreases clauses, declaration count and all bytes outside target proof bodies remain protected. Client files cannot be supplied in the payload and must be copied unchanged by any future evaluator.

The entire body must parse under a narrow grammar: if/else (including else-if), assertions of comparisons, and self-recursive calls with two arguments. Expressions allow s/t, bounded decimal integers, empty sequences, Total(expression), sequence length, indexing/slices, unary +/- and binary +/-. Comparisons allow <, <=, >, >=, == and !=. No arbitrary function calls, variables, declarations, reveals, comments, assumptions, loops, axioms or attributes are permitted. Limits are 128 KiB raw response, 2,048 body tokens, 64 statements, depth 24, 128 binary operations per expression level, and 24 postfix operations per atom. The grammar is deliberately incomplete relative to Dafny.

**Treatment constraint:** each helper can call only itself, not the other helper. This prevents the separate condition from delegating its proof to the already proved A helper, but restricts the search space and must be explicit in future prompts and interpretations. Copying the same inductive proof structure into both bodies remains permitted. It does not establish that separate is cognitively harder, and source length/edit count differ across conditions.

The guard is syntactic. Empty bodies, wrong recursive arguments and nondecreasing calls remain accepted by design, then fail Dafny according to the saved controls. It does not establish termination, semantic types or proof validity. Syntax trees are audit structures, not proof-prerequisite graphs.

Six offline test methods cover all 12 revision-003 fixtures byte-for-byte, protected-source changes, verification bypass attempts, cross-helper delegation, malformed syntax/resource bounds, ambiguous payloads and regression for the revision-002 extra-brace generation bug. Every accepted fixture is identical to the corresponding source already verified on job 55305635. Since no new proof bytes were generated, another compute run is unnecessary. `provider-guard-replay.json` links the byte-preservation check to the saved fixture outcomes; `provider-guard-freeze.json` pins guard code and tests.

A future full evaluator must hash/check the immutable clients and providers, run whole-included-repository verification and log all output. No paid pilot or prompt protocol is yet authorized or frozen for this family.
