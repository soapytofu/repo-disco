# Two independent AWS growth tasks

The immutable seed is the exact five-file candidate accepted at growth-001 slot-04, including slot-02’s `ReadU16Frame` and slot-04’s `ReadFramePair`. It is the earliest complete accepted AWS lineage by slot order. The saved native review is replayable and contains 77 passed units, zero errors and warnings. This reuses one existing observation; it is not a new verifier run or full AWS/MPL coverage. Exact sources, raw evidence, upstream Git blob pins and copy origins are retained under `seed/`.

`aws-batch` adds `ReadCountedFrames(input, count)`. It must handle arbitrary natural counts recursively, preserve payload order, accept exactly when enough complete frames exist, and return an exact suffix and canonical re-encoding identity. Count zero succeeds with unchanged input even if the input is malformed. Fixed predicates describe feasibility and payload bounds; the fixed encoder specifies the representation without supplying a completed decoder.

`aws-tagged` adds `ReadTaggedBoundedPair(input, tag, budget)`. It uses the existing pair format, rejects malformed pairs, empty or mismatching tags, and over-budget payloads. The budget counts the untagged first payload plus the second payload, excluding the tag, headers and suffix. Success returns the exact untagged first payload, second payload and suffix, with a re-encoding identity restoring the tag. The inclusive budget boundary, tag-only first payload, empty second payload and malformed trailing suffix are specified explicitly.

Each task is a separate six-file workspace: the same five saved seed files plus one new file with exactly one editable expression body. All signatures, contracts, imports, types, helper definitions and decreases remain fixed. Direct correct implementations remain admissible; call or reveal counts are descriptive reuse measurements. The new tasks are independent extensions of the saved base, not a new sequential collection. These are development instances, not held-out families, and their empirical difficulty is unmeasured.

`cases.json` supplies explicit roots, exact source hashes, expected named semantic targets and 14 analyst cases. Run only `counted-reference` and `tagged-reference` first. The twelve remaining cases comprise four deliberately wrong bodies per task, one unproved immutable-helper control per task, and one staged-but-omitted bad target per task. The last must expose missing coverage despite native success of the base; an unproved helper must remain a failure even if its caller passes under the assumed contract. These control mutations are outside the model’s permitted edit scope. New actual Dafny unit labels and all mathematical outcomes remain **UNKNOWN** until compute qualification; function methods need their actual emitted units, not guessed correctness labels.
