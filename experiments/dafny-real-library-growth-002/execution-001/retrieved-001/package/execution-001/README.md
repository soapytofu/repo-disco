# Eight independent extension attempts

This new host adapts the completed twelve-call library runner. It removes the
child-dispatch and conditional-expansion paths: four fixed task inputs each
receive two independent responses, in forward then reverse task order. All
saved base sources are immutable, including any earlier accepted model code.
No current response supplies context to another trial.

The parser, lexical protected-body guard, native evidence reviewer, request
gate and scoped credential transport are copied with recorded origins. The
guard admits ordinary Dafny proof/program syntax inside one fixed body; it is
not a complete parser. The pinned native verifier decides syntax, typing,
termination and proof success. Only complete source-bound native coverage may
qualify an addition. Missing/omitted obligations, unproved fixed helpers, stale
evidence and changed source/tool hashes cannot qualify success.

Each request is reserved durably before dispatch; provider ambiguity closes the
run without retry. The canonical allocation claim is exclusive, permanent and
outside the package/output directories. The cumulative budget must retain all
three prior allocations exactly and add eight within the user's 100-call cap.
Authorization binds the precise runtime, scope, budget, output and claim paths,
and expires within 24 hours. Frozen code alone does not issue authorization.

The host performs native tool/version checks on the compute node before lazy
private-handoff consumption. Serial verification receives one CPU and uses the
qualified project-specific toolchain, flags and resource limits. Every response,
candidate, command, native stream, CSV, resource report and durable event is
saved. Unchanged accepted base code is always verified in the complete scope.

Ordinary proof failures and complete closed verifier-resource failures count as
unsuccessful attempts without changing later declared inputs. Parser/body-policy
rejections consume their single request without native invocation. Frontend
errors, new warnings, incomplete coverage, outer timeouts, integrity drift,
missing provenance or ambiguous provider outcomes stop all later dispatch.
There is no repair loop, automatic retry, resumption or adaptive sampling.

The offline collection reviewer reconstructs every saved prompt and candidate,
replays native coverage, and checks request IDs, retry counts, token totals and
the externally pinned authorization/allocation claim. It also audits stopped
collections without inventing a proof score or token count for an unreturned
request. Synthetic observations are rejected by the production review entry.

Offline tests use fake transports and synthetic native records or Python child
processes. They never call a provider, access credentials or invoke Dafny. The
qualification gate now binds four passing references and 26 matching controls;
four exact payloads and their eight-slot order are frozen. Execution additionally
requires the reviewed runtime manifest, successful manifest-only preflight,
fresh private handoff and hash-bound authorization. No execution state is
created by these offline tests or prompt preparation.
