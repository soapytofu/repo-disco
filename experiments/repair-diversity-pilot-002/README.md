The design is **4 instances × shared/separate × detailed verifier feedback/failure
notice only × 2 fresh responses = 32 requests**. There are eight failing
workspaces and sixteen distinct prompt payloads; these are four semantic
instances, not 32 independently sampled tasks. The sixteen cells appear once in
the first block and in reversed order in the second block, giving each cell mean
position 16.5. This is ordinal counterbalancing, not paired random seeds or a
claim of perfect transition balance.

Each request starts from the same frozen failing base for its workspace, in an
independent context. Both feedback conditions see identical source bytes,
contracts, file includes, syntax and allowed symbols. The detailed arm receives
the original exit code/stdout/stderr, removing only the incidental CSV
`Results File` line; the other arm receives only the same failure notice. No
positive proof, alternate proof, counterexample, failure-type annotation or
analyst repair advice enters the model context. One request is the whole repair
attempt: no further feedback loop, transport retry, replacement or reassignment.

Model/settings remain `global.anthropic.claude-opus-4-5-20251101-v1:0`,
`us-east-1`, temperature 1.0 and 4,096 maximum output tokens per response.
The maximum output allowance is 131,072 tokens; actual inputs, outputs and cost
must be measured, not inferred from that ceiling.

Primary success is guard-admitted strict whole-workspace verification: exit 0,
nonzero verified obligations, zero errors and zero warnings. Truncation, envelope
or body rejection and proof failure remain unsuccessful repairs. Execution
failures and reserved calls must also be reported, without replacement trials.
Secondary measurements use the existing `target_metrics.py` interpreter with
reference-CSV-derived named scopes, distinct immutable-provider checks and
dependency-closed clients. A client that verifies against an unproved helper's
contract does not receive repository-success credit. Self-recursion is verified
inside its named helper, not represented as a cyclic cross-helper edge.

Shared has one editable body and a protected forwarding helper; separate has two
equivalent bodies and permits copying. This changes a helper dependency edge,
output work and source length. There is no depth factor,
held-out family, natural-error prevalence estimate or general causal sharing
claim. Report the four instances and each sharing/feedback cell separately;
retain failures and avoid pooling with previous pilot scores.

`prepare.py measurements` assembles the eight named scopes and 24 saved control
measurements without running Dafny. It writes a draft coordinator gate. The final
gate must bind each group's `results-review.json`, flat fixture/runtime manifests,
the protocol freeze, measurement scope and a published source commit.
`prepare.py freeze` then creates the runner-compatible `parents.json`,
`trials.json`, `settings.json`, exact failing/template workspaces, requests,
standalone copied policy/registry and a hash manifest. `prepare.py check`
reproduces that future freeze exactly offline. The default command only reports
status; it cannot silently freeze or dispatch a study.

Offline checks: `python3 -B test_plan.py`. Frozen earlier plans, policies, source
files and results are read-only inputs throughout this preparation.
