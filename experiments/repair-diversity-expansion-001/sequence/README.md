# Adjacent-run compression idempotence (D2-M1)

Status: **constructed, not yet Dafny-verified**. Six offline construction/staging tests pass. No model calls. This is a development repair instance of the existing corpus plan, not a held-out family or a complete shallow/deep generation matrix.

`Compress` removes adjacent duplicate elements. `Clean` is an opaque recursive predicate stating that consecutive elements differ. The editable lemma proves a clean sequence is a fixed point of compression. Its induction must first obtain the tail invariant, recursively apply the same contract to the tail, obtain the unequal-neighbor condition, then use the protected keep-step equation. The independent alternative uses separate zero/one-element branches and a different legal fact order with a local tail alias. It is an alternative proof of the same instance, not an independent task family.

An immutable `Invariant` module proves that every compressed output is clean. Two immutable clients use that prerequisite and the editable fixed-point lemma to prove compression idempotent on an arbitrary input and on two concatenated inputs. The model-facing helper cannot import the internal `Drop` contract or unfold `Compress`/`Clean`. No idempotence theorem is exported to the helper. Provider correctness, alternative proof correctness and negative outcomes still require compute-node verification.

Shared mode edits one helper body and keeps a protected forwarding helper. Separate mode edits two equivalent helper bodies and permits copying. Providers, client meanings, signatures, contracts, `{:induction false}` and termination measures are identical across conditions. The number of editable bodies and output work differ; this does not isolate a pure cognitive-sharing effect or establish a necessary proof depth.

The primary analyst fault recurses without first establishing the opaque tail invariant. Other controls omit the unequal-neighbor fact or induction hypothesis, recurse on the wrong suffix, use the wrong base-case boundary, fail termination, or call a hidden helper. The 20 planned checks comprise four reference/alternative successes, twelve ordinary proof failures, two termination failures and two hidden-export name-resolution failures. Parse errors never count as expected proof failures. These are analyst-constructed faults, not observed model errors.

`generate.py` deterministically emits the fixtures, task registry and exact source manifest. `verify.py` refuses execution outside a compute allocation, checks pinned Dafny 4.11.0, runs each source once, and preserves full stdout/stderr, byte-exact CSV, source hashes and a summary. `verify.sbatch` is a template for the parent coordinator after it reconfirms live `test` preemption settings and stages this complete directory. No job is submitted by generation or tests. Production output-guard integration and model prompts remain pending; the registry declares the pure `K.Compress`/`K.Clean` expressions and self-recursion required by the new interface.
